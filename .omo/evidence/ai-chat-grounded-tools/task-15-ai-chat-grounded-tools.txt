Scope
-----
Tests only, plus two type fixes required for the new surface to compile:

1. app/utils/aiChat.test.ts (+33 lines)
   - "should carry documentId as a top-level body key": asserts the request
     body sent to /api/ai.chat has `documentId` at the top level and that
     `forwardedProps` stays `{}` - the document must never ride inside
     forwardedProps.
   - "should omit documentId when no document is in scope": asserts the body
     has no `documentId` property when the connection was built without one.

2. app/components/AIChat/AIChatContext.test.tsx (+55 lines)
   - "hands a pending prompt to the panel exactly once" - consume is one-shot.
   - "keeps the pending prompt across a close and reopen" - the prefill lives
     outside panel state, so a close/reopen does not lose it.
   - "puts a consumed prompt back for the next send" - restorePendingPrompt
     returns an unsent prefill.
   - "carries the document a prefilled prompt refers to" - documentId survives
     the prefill channel.

3. app/components/AIChat/AIChatPanel.tsx (type fix)
   - `styled(Button<{ $neutral?: boolean }>)` was invalid: Button is a generic
     function component `Button<T extends React.ElementType>`, so the generic
     cannot be instantiated at the JSX element type. Moved the transient prop
     to the styled wrapper: `styled(Button)<{ $neutral?: boolean }>`.

4. app/components/AIChat/AIChatContext.tsx (type fix)
   - `openAIChatPanel(prompt?: string | AiChatPrefill)` passed the union
     straight to `setPendingPrompt(AiChatPrefill | null)`. A bare string is now
     wrapped as `{ prompt }`. Behaviour for callers is unchanged, and the
     string form is thereby covered by the existing prefill tests.

5. app/components/AIChat/AIChatTrigger.test.tsx (type fix)
   - The three `AIChatControls` mock literals were missing the newly added
     `setPendingPrompt` / `consumePendingPrompt` members; added no-op stubs.
