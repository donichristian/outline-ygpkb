## 5. Middleware/terminal ordering spike

`chat()` with a middleware whose `onFinish` deliberately awaits 50 ms, read
through `toServerSentEventsResponse`. Timestamps relative to run start:

    ORDERING_MS: {"terminalEventSeen":25,"onFinishResolved":79,"streamClosed":79}
    ORDERING_VERDICT: onFinish completes BEFORE the SSE stream closes
    TERMINAL_VS_HOOK: reader sees RUN_FINISHED BEFORE onFinish resolves

Mechanism: the engine yields the terminal chunk, then `await runTerminalHook()`
before the async iterable reports done (`activities/chat/index.js:504`); the SSE
helper closes the byte stream only after the source iterable is exhausted.

Consequence for W1 todo 5: an `onFinish`/`onError`/`onAbort` hook IS awaited
before the SSE stream closes, so a persistence commit inside the hook is
durable before the consumer sees end-of-stream. The terminal RUN_FINISHED
event, however, is delivered BEFORE the hook resolves (as it is today, where
`finish()` pushes the terminal frame before `appendTurn` commits). A client
that acts on RUN_FINISHED and immediately re-reads history can race the commit;
that race exists in the current implementation and is not introduced by this
adapter.

Fallback is NOT required: the ordering on `chat()` + `toServerSentEventsResponse`
satisfies "row committed before the response stream completes". W1 todo 4 may
use middleware hooks; no manual `StreamProcessor` is needed. If a future
requirement tightens the guarantee to "committed before RUN_FINISHED is
delivered", that would require withholding the terminal event, which this path
does not do.

## 7. CommonJS build seam (ESM-only packages)

Both packages publish an `import`-only exports map. Direct `require()` fails:

    ERR @tanstack/ai ERR_PACKAGE_PATH_NOT_EXPORTED No "exports" main defined
    ERR @tanstack/ai-openai/compatible ERR_PACKAGE_PATH_NOT_EXPORTED Package subpath './compatible' is not defined by "exports"

The adapter therefore loads them through `loadOpenaiCompatible()`
(`server/routes/api/ai/tanstack.ts`), whose dynamic `import()` is assembled with
`new Function` so SWC's CommonJS transform cannot rewrite it to `require()`.
Proven from a real CommonJS process:

    CJS_SEAM: dynamicImport+chat OK
    CJS_EVENT_SEQUENCE: ["RUN_STARTED","TEXT_MESSAGE_START","TEXT_MESSAGE_CONTENT","TEXT_MESSAGE_END","RUN_FINISHED"]

Vitest caveat (for W1/W6 test authoring): inside Vitest's VM context
`new Function("return import(...)")` throws
`TypeError: A dynamic import callback was not specified`. Tests that call the
factory must mock `./tanstack` (or the two packages). The production path is
unaffected; it runs in plain Node, where the seam above is verified.
