VERDICT: the installed @tanstack/ai-client DOES expose a usable queue
(`queue: { whenBusy, drain, onOverflow, maxSize }` + `cancelQueued(id)`).
BUT the queue is INSTANCE state on a `ChatClient`, and this panel builds a NEW
headless `ChatClient` for EVERY turn (`sendTurn` -> `new ChatClient(...)`,
threadId fixed at construction). A per-turn client cannot carry its queue across
the turn boundary, so the library queue is unusable here.
=> The queue is implemented as PANEL STATE: an ordered `queued: QueuedTurn[]`
   (`{ id, content }`), authoritative copy in `queueRef` for the async drain,
   rendered copy in `queued` state. Semantics mirror the library exactly:
   FIFO, drain after a settled turn, flush on stop/error, per-item cancel.
